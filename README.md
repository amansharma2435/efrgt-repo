# AI-Powered Document Question Answering System using Retrieval-Augmented Generation (RAG)

A small web app that lets you upload a PDF and ask questions about it. The answer is written by Google Gemini, but Gemini only sees a few passages retrieved from the PDF. If those passages do not contain the answer, the app is instructed to say the information was not found.

This repository is meant to be read by a B.Tech CSE student and explained in a viva. Each stage of the pipeline is a separate Python module.

## How a question is answered

```
PDF file
  │
  ▼
pdf_processing.py        PyMuPDF reads each page and keeps the page number
  │
  ▼
text_chunking.py         LangChain splits each page into overlapping chunks
  │
  ▼
embeddings.py            Sentence Transformers turns every chunk into a vector
  │
  ▼
vector_database.py       FAISS stores the vectors and returns the top 3 matches
  │
  ▼
rag_pipeline.py          Gemini answers from those 3 passages only
  │
  ▼
app.py                   Streamlit chat, with the passage and page under the answer
```

Retrieval-augmented generation means the language model is not asked to remember the PDF. The program searches the PDF first, then the model writes an answer from the search result. That is why the answer can cite a page.

## Project layout

| File | Role |
| --- | --- |
| `docqa/pdf_processing.py` | Validate the upload and extract text page by page |
| `docqa/text_chunking.py` | Split pages into overlapping chunks with metadata |
| `docqa/embeddings.py` | Sentence Transformers embedding model |
| `docqa/vector_database.py` | In-memory FAISS index |
| `docqa/rag_pipeline.py` | Prompt, Gemini call, and cited passages |
| `docqa/indexing.py` | Connect extraction, chunking, embeddings, and FAISS |
| `docqa/app.py` | Streamlit interface |
| `app.py` | Command used to start the website |
| `samples/campus_handbook.pdf` | Short example PDF |
| `tests/` | Automated tests for each stage |

Uploaded PDFs stay in the Streamlit session memory. They are not written to a database.

## Requirements

- Python 3.10 or newer (tested with 3.12)
- Internet access the first time you run the app, so the embedding model can be downloaded from Hugging Face
- Internet access on every question, because the answer is generated by the Gemini API
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey)

Indexing a PDF does not use the API key. Asking a question does. Without a key, upload and the tests of extraction, chunking, and retrieval still work. The live Gemini test is skipped, and the chat shows a clear error instead of a made-up answer.

The embedding model is `sentence-transformers/all-MiniLM-L6-v2`. It runs on CPU. A GPU is not required.

Scanned PDFs (pages that are photographs of paper) have no text layer. This project does not include OCR, and it will say that no text was found.

## Installation

From the repository root:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

On Debian or Ubuntu, if `python3 -m venv` says `ensurepip` is missing:

```bash
sudo apt-get update
sudo apt-get install -y python3.12-venv
```

Create a local env file and paste your key into it:

```bash
cp .env.example .env
```

`.env` should look like this (use your own key):

```bash
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-2.5-flash
```

You can instead copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and put the same values there. The app checks environment variables first, then Streamlit secrets. The key is never printed in the sidebar or in error text.

If Gemini returns a "model not found" error, set `GEMINI_MODEL` to a Flash model id currently listed in Google AI Studio.

## Run the app

```bash
source .venv/bin/activate
streamlit run app.py
```

Streamlit prints a local URL, usually `http://localhost:8501`.

1. Open the sidebar and upload a PDF, or use `samples/campus_handbook.pdf`.
2. Wait until the sidebar shows the file name, page count, and chunk count.
3. Ask a question in the chat box.

Questions that match the sample handbook:

- When does the central library close on weekdays?
- How many days does a student have to request a full refund?
- Which room is used for Data Structures?

A question the handbook cannot answer, such as "What is the cafeteria menu on Mars?", should come back as: "The information was not found in the document."

Open a source row under the answer to read the passage, the file name, the PDF page number, and the cosine similarity score.

To recreate the sample PDF:

```bash
python scripts/create_sample_pdf.py
```

## Run the tests

```bash
source .venv/bin/activate
pytest
```

The first retrieval test downloads the embedding model (about 90 MB) into the Hugging Face cache. Later runs reuse it.

| Test file | What it checks |
| --- | --- |
| `tests/test_pdf_processing.py` | Page text, empty page 2, non-PDF rejection, encrypted PDF rejection |
| `tests/test_chunking.py` | Overlap, metadata, and that pages are not merged |
| `tests/test_vector_database.py` | Top-3 FAISS search, and real embeddings finding the refund page |
| `tests/test_rag_pipeline.py` | Prompt rules, pipeline wiring, missing API key, optional live Gemini call |
| `tests/test_app.py` | The Streamlit page renders and does not display a key |

`test_live_gemini_answers_from_the_handbook` calls Gemini only when `GEMINI_API_KEY` or `GOOGLE_API_KEY` is set. Otherwise pytest skips it. A skipped test is not a successful API call.

## What to say in a viva

**Why chunk the PDF?** A whole document does not fit cleanly into a similarity search, and a long prompt is harder to ground. Short overlapping passages are the units we search.

**Why overlap?** The splitter may cut a sentence in half. Repeating a few characters at the boundary keeps that sentence whole inside one of the two chunks.

**Why split per page?** A chunk never mixes two pages, so the citation page number is the page the words came from.

**Why vectors?** `all-MiniLM-L6-v2` maps text to a list of 384 numbers. Similar meanings land near each other. The question is embedded with the same model, then compared with every chunk.

**Why normalise the vectors?** After each vector is scaled to length 1, the inner product is the cosine similarity. FAISS `IndexFlatIP` ranks by that score. The search is exact: every chunk is compared. That is appropriate for a handful of documents.

**Why top 3?** The interface always retrieves three passages (or fewer, if the PDF produced fewer chunks) and shows each one. The model is told to use only that context.

**Why tell Gemini to refuse?** The model was trained on other books and websites. The prompt forbids outside knowledge and gives it an exact sentence to use when the passages are not enough.

## Settings

The sidebar can change the chunk size and the overlap. Those values apply to the next upload, or when you press **Rebuild index with these settings**. Retrieval stays at 3 passages.

Default chunk size is 700 characters and overlap is 120 characters.

## Security

- The Gemini key is read from `GEMINI_API_KEY` or `GOOGLE_API_KEY`, or from Streamlit secrets.
- No key is hard-coded.
- Error text is passed through a redaction step that strips strings shaped like API keys.
- Upload size is limited to 25 MB.
- The file name shown in the app is only the base name, not a directory path.

## Limits

- English text works best with MiniLM.
- Image-only PDFs are rejected with an explanation.
- Password-protected PDFs are rejected.
- The FAISS index is in memory and disappears when the Streamlit process stops.
- Answers require the Gemini API. This project will not invent an answer when the call cannot be made.
